Overview

Making internal testing more useful

BuildPulse is a Unity QA telemetry and performance reporting tool designed to make internal testing easier to analyze and act on.

Instead of depending on testers to manually document technical information, BuildPulse gathers useful runtime context during the test session.

The resulting data can then be packaged into a consistent report and delivered into the team's development workflow.

Collection

Capturing the context behind a test session

BuildPulse can collect system information, graphics settings, runtime performance data and gameplay-related diagnostic information during a session.

The goal is to preserve enough technical context that developers can investigate a report without requiring the tester to manually reconstruct their environment.

Collection systems can be enabled independently so teams can gather the information they need without forcing every category into every test session.

Performance Telemetry

Turning “it ran badly” into measurable data

Performance collection includes average, minimum and maximum FPS, together with 1% and 0.1% low measurements.

Frame, CPU, main-thread and render timings provide more diagnostic value than relying on a single FPS measurement.

Memory sampling and worst-frame capture help preserve short-lived performance problems that could otherwise disappear inside session averages.

Delivery & Webhooks

Moving reports into the team's workflow

Collecting telemetry is only useful if the resulting report reaches the people who need to investigate it.

BuildPulse includes configurable webhook delivery so reports can be sent directly into an external development or QA workflow.

Connection testing and validation are exposed inside the editor, allowing delivery problems to be found before a test build is distributed.

Configuration & Validation

A tool other developers can actually configure

BuildPulse exposes configuration for the execution environment, telemetry collection and performance sampling through the Unity editor.

Parameters such as warmup time, memory sampling and worst-frame collection can be adjusted without modifying the underlying code.

Setup and validation workflows are built into the editor interface so a project can confirm BuildPulse is ready before producing a test build.

Structured Reporting

Turning a test session into structured data

BuildPulse packages captured session information into structured JSON rather than relying on free-form technical notes.

System, configuration, performance and diagnostic information are separated into predictable groups that can be inspected by developers or passed into additional tooling.

The report format is versioned so the schema can evolve while remaining identifiable across builds and tool revisions.
